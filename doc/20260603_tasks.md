可以。**Ada4DIR 这一部分的核心目标是：把它从一个 All-in-One restoration model，改造成几个 single-degradation tools，用来补全我们 Agent 的 toolbox。** 这样之后 Agent 就不需要再把 All-in-One 当作 Blur / Noise / Dark 的替代工具，而是真的可以按 degradation type 逐步调用 specific tools，形成 cascade trajectory。

这里我把会议里关于 **Ada4DIR** 的部分单独整理成下面这个版本。

---

## 1. 为什么现在要做 Ada4DIR

之前的问题是：我们的 toolbox 对 **Haze** 有 specific tool，但对 **Blur / Noise / Dark** 没有真正的 single-degradation tool。所以在这些 degradation 上，Agent 只能调用 All-in-One model。这样会导致两个问题：

第一，Agent 和 All-in-One 的区别不明显。因为如果 Blur / Noise / Dark 都只能调用 All-in-One，那 Agent 的很多 trajectory 其实只是绕了一圈又用了 All-in-One。

第二，可解释性故事会变弱。我们想讲的是：Agent 先识别 degradation，然后一步步调用对应工具，比如先 denoise，再 deblur，再 dehaze。但如果工具本身还是一个黑盒 All-in-One，就很难说每一步到底在处理什么。会议里王老师也明确指出，如果没有 Blur / Noise / Dark 的 specific tools，toolbox 就是不完整的。

所以 Ada4DIR 的作用不是作为一个普通 baseline，而是用来 **训练或微调出几个 degradation-specific tools** ：

* Blur-specific tool
* Noise-specific tool
* Dark-specific tool

Haze 已经有现成 specific tool，所以 Ada4DIR 目前最关键的是补齐这三个缺口。

---

## 2. 最终采用的技术路线

会议里讨论过几种方案，但最后比较明确的路线是：

**不要一开始大改 Ada4DIR 的模型结构。先用最小改动方案：加载 Ada4DIR 的 pretrained / All-in-One checkpoint，然后只用单一 degradation 的数据继续 fine-tune。**

也就是说，不是把 Ada4DIR 里面的其他模块强行删掉，也不是先重写 expert / fusion / classifier，而是先保持模型结构基本不动，只改训练数据和训练设置。比如要训练 deblur tool，就只喂 blur 数据；要训练 denoise tool，就只喂 noise 数据；要训练 dark restoration tool，就只喂 dark 数据。会议里认为这是最快、最稳、最容易验证的方案。

可以把它理解成：

> Ada4DIR 原本是一个 multi-degradation / All-in-One model。
> 我们现在用它的 checkpoint 作为初始化，然后针对单一 degradation 做后训练，让模型往某个 specific tool 的方向偏移。

这个路线的通过标准也很直接：**只要 fine-tuned model 在对应 single-degradation test set 上比原始 All-in-One 更好，它就可以被注册成对应的 specific tool。**

---

## 3. 具体要训练哪些模型

当前最应该做的是三个模型：

| Tool 名称     | 训练数据                          | Validation       | 用途                                     |
| ------------- | --------------------------------- | ---------------- | ---------------------------------------- |
| Ada4DIR-Blur  | blur-only degraded / clean pairs  | blur validation  | 作为 deblur tool                         |
| Ada4DIR-Noise | noise-only degraded / clean pairs | noise validation | 作为 denoise tool                        |
| Ada4DIR-Dark  | dark-only degraded / clean pairs  | dark validation  | 作为 dark restoration / enhancement tool |

也可以把 Haze 纳入统一训练框架，但从会议内容看， **Haze 不是最急的** ，因为我们已经有 haze-specific tool。当前 Ada4DIR 的主要价值是补齐 Blur / Noise / Dark。

---

## 4. 具体工程上要怎么做

### Step 1：单独拉一个 Ada4DIR repo

会议里建议不要直接在当前 `tools` 里面已有的 repo 上改，因为那个 repo 可能已经被改过。更稳妥的做法是在 restoration agent 项目旁边或主目录下重新拉一个 standalone 的 Ada4DIR repo。这样训练实验和现有 tool wrapper 不会互相污染。

你要做的是：

1. 找到 Ada4DIR 官方或当前使用的 repo。
2. 在 Genkai 上单独 clone 一份。
3. 确认 training script、validation script、checkpoint loading 都能跑。
4. 不要先改复杂模型结构，只先让原始训练流程能跑起来。

---

### Step 2：确认 Ada4DIR 的数据组织方式

会议里提到，Ada4DIR 的代码本身应该已经有不同 degradation subset，比如类似：

* train noise
* train blur
* train dark
* train haze

也就是说，它本来就有按 degradation 分开的训练部分。我们要利用这个特点，把原来的 multi-degradation training 改成 single-degradation fine-tuning。

你需要确认：

1. Blur 数据在哪里。
2. Noise 数据在哪里。
3. Dark 数据在哪里。
4. Clean GT 如何对应 degraded image。
5. Validation 是否也能按 degradation type 单独切分。
6. Training config 里是否有类似 “每 16 个 batch 切换 degradation” 的逻辑。

---

### Step 3：改训练逻辑：从多类切换改成单类固定

会议里你解释说，Ada4DIR 原始训练可能是四类 degradation 联合训练，比如每 16 个 batch 换一种 degradation，并且模型里可能有 degradation classifier、expert/module、fusion 之类的结构。

我们现在要做的最小改动是：

* 训练 Blur tool 时，始终只读 blur subset。
* 训练 Noise tool 时，始终只读 noise subset。
* 训练 Dark tool 时，始终只读 dark subset。
* 如果代码里需要 degradation label，就固定成当前 degradation 的 label。
* Validation 也固定成同一个 degradation。

也就是说，原本是：

```text
blur -> noise -> dark -> haze -> blur -> ...
```

现在改成：

```text
blur -> blur -> blur -> blur -> ...
```

或者：

```text
noise -> noise -> noise -> noise -> ...
```

这样模型会被继续拉向某一个 degradation-specific 的能力。

---

### Step 4：加载 Ada4DIR checkpoint 后 fine-tune

不要优先从 scratch 训练。会议里的判断是，最快的方式是：

1. 加载 Ada4DIR 原本的 pretrained / All-in-One checkpoint。
2. 用单一 degradation 数据继续训练几个 epoch。
3. 看 validation loss 是否下降。
4. 看 PSNR / SSIM 是否超过原始 Ada4DIR All-in-One。

这个过程有点像 SFT：原模型已经会做 general restoration，现在我们让它更 specific。

---

## 5. 先做哪个 degradation

建议先做一个 proof-of-concept，不要三个一起开。

我建议顺序是：

1. **Noise-specific tool**
2. **Blur-specific tool**
3. **Dark-specific tool**

原因是 noise 通常更容易从 metric 上看到变化，denoise 的 single task 也比较清楚。如果 noise 跑通，说明代码路线没问题，再复制到 blur 和 dark。

会议里的判断也是：先用最简单方案跑一个，如果有效，后面的复杂模型改动都可以先不做。

---

## 6. 怎么判断 Ada4DIR fine-tuning 成功

成功标准不是“模型完全失去其他 degradation 的能力”，而是：

> 在目标 single-degradation 上，fine-tuned Ada4DIR tool 要比原始 All-in-One 更好。

比如训练了 Ada4DIR-Blur，那么就比较：

| Method                  | Blur-only PSNR / SSIM |
| ----------------------- | --------------------- |
| 原始 Ada4DIR All-in-One | baseline              |
| Fine-tuned Ada4DIR-Blur | 应该更高              |

如果 Ada4DIR-Blur 在 blur-only 上比原始 All-in-One 高，就可以作为 deblur tool 注册进 toolbox。哪怕它仍然能处理一点 noise 或 dark，也没关系，因为在 Agent 里我们只把它当作 blur tool 使用。会议中也明确说，不需要纠结它是否完全丧失其他能力，结果上 target degradation 更好就可以。

---

## 7. 额外要测试：normal inference vs one-hot inference

你在会上担心一个问题：如果 fine-tuned tool 虽然叫 deblur，但它实际推理时可能还会顺手处理其他 degradation，这会不会影响 cascade？

会议里的解决方式是：训练完以后可以测试两种 inference setting。

第一种是正常推理：

```text
直接输入 degraded image，让模型自己输出 restored image。
```

第二种是手动指定 degradation / one-hot：

```text
如果 Ada4DIR 内部有 degradation distribution 或 fusion weight，
就手动把目标 degradation 的权重设成 1，
其他 degradation 的权重设成 0。
```

然后比较：

* normal inference 是否比 All-in-One 好；
* one-hot inference 是否比 All-in-One 好；
* one-hot 后性能是否明显下降。

如果 one-hot 后性能仍然好，说明这个 specific tool 更稳定，也更适合放进 Agent 的 cascade。

---

## 8. 论文里怎么讲 Ada4DIR 这一部分

这个地方要注意写法。

会议里的建议是： **不要把主叙事写成“我们把 All-in-One 拿来微调了一下”** ，因为这样会让 reviewer 觉得我们还是依赖 All-in-One，没有真正构建 specific tools。更合适的写法是：

> For degradation types where reliable off-the-shelf remote-sensing tools are unavailable, we train degradation-specific dense prediction restoration tools using single-degradation training data.

中文意思就是：

> 对于没有可靠开源遥感工具的退化类型，我们基于 dense prediction restoration 架构，使用单一退化数据训练对应的 degradation-specific tools。

方法细节里可以诚实说明初始化和训练方式，例如使用已有 restoration checkpoint 初始化、再用 single-degradation data fine-tune。但在 storyline 上，重点应该是：

* 我们构建了 degradation-specific tools；
* 这些 tools 覆盖 Blur / Noise / Dark；
* 它们在对应 single-degradation task 上优于 All-in-One；
* 因此 Agent 可以不用把 All-in-One 当工具，而是真正用 specific tools 做 cascade。

## 9. 这部分最后要产出的东西

Ada4DIR 这一部分最后应该产出五类结果。

### 1. 三个 checkpoint

```text
Ada4DIR-Blur
Ada4DIR-Noise
Ada4DIR-Dark
```

每个 checkpoint 都是用对应 single-degradation data fine-tuned 出来的。

### 2. 三个 tool wrapper

每个 wrapper 要能做到：

```text
input degraded image -> output restored image
```

并且要符合当前 toolbox 的 play-down/output 结构。

### 3. Single-degradation 对比表

至少要有：

| Degradation | Original Ada4DIR All-in-One | Fine-tuned Ada4DIR-specific tool |          Δ |
| ----------- | --------------------------: | -------------------------------: | ----------: |
| Blur        |                    baseline |                 higher is better | improvement |
| Noise       |                    baseline |                 higher is better | improvement |
| Dark        |                    baseline |                 higher is better | improvement |

指标可以先用 PSNR / SSIM。

### 4. Cascade / multi-degradation 大表中的 Agent 结果

当 Blur / Noise / Dark tools 都补齐后，Agent 的 toolbox 就完整了。之后 multi-degradation 表格里，Agent 可以真的按顺序调用：

```text
denoise -> deblur -> dehaze -> dark restoration
```

而不是调用 All-in-One。

### 5. Training details

需要记录：

* 使用的数据 subset；
* degradation 类型；
* 初始化 checkpoint；
* learning rate；
* epoch 数；
* batch size；
* validation set；
* best checkpoint selection rule；
* PSNR / SSIM evaluation script。

这些后面要写进实验设置或 appendix。
